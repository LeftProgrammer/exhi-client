# 白马展厅 · 科研创新 · 中控通信协议

> 本文件由项目开发方定义，供中控平台按此格式发送指令。
> 协议基于 WebSocket（UEC 转发服务），消息体为 JSON。

---

## 一、项目架构（5 屏联动 · 分布式 WS 转发）

| 屏幕      | displayId   | hub.json id | 说明                       |
| --------- | ----------- | ----------- | -------------------------- |
| 主屏      | `main`      | `research-main` | 地图 + 点位详情 + 右侧菜单 |
| 左上副屏  | `top-left`  | `research-tl`   | 工程点位详情图文展示       |
| 左下副屏  | `bottom-left` | `research-bl` | 图片轮播、卡片堆叠展示     |
| 右上副屏  | `top-right` | `research-tr`   | 工程点位详情图文展示       |
| 右下副屏  | `bottom-right` | `research-br` | 图片轮播、卡片堆叠展示    |

**通信链路：**

```
中控 WS ──→ main 屏（只发 main）
               ↓ syncPoint(id) / syncIdle()
               ↓ forwarder → UEC WS 转发
               ↓   { to: "research-tl", msg: {...} }
               ↓   { to: "research-bl", msg: {...} }
               ↓   { to: "research-tr", msg: {...} }
               ↓   { to: "research-br", msg: {...} }
          ┌────┴────┬───────┬───────┐
          ↓         ↓       ↓       ↓
       UEC WS   UEC WS UEC WS UEC WS
          ↓         ↓       ↓       ↓
      top-left  bottom-left top-right bottom-right
      (research-tl) (research-bl) (research-tr) (research-br)
```

- 中控 WS 指令**只发给 main 屏**（通过 `hub.json` 中不同 `id` 区分）。
- main 收到指令后调用 `useScreenSync`，通过 **UEC WS 转发**到 4 个副屏（每个副屏各自连 WS，独立接收）。
- `home` 指令中控可群发给所有 5 屏，确保回待机万无一失。
- 副屏各自注册全部指令，收到主屏转发的指令后通过 `syncXxx` 应用到本屏视图，**不再二次转发**。

## 二、中控 → 设备（接收指令）

设备连接 WS 后，监听中控发来的消息，根据 `cmd` 字段执行操作。

| 操作         | 消息格式                                    | 说明                          |
| ------------ | ------------------------------------------- | ----------------------------- |
| **回首页**   | `{ "cmd": "home" }`                         | 返回待机（清空选中点位）      |
| **选中点位** | `{ "cmd": "point", "id": "baima-bridge" }`  | 选中指定工程点位              |
| **选中点位** | `{ "cmd": "goto", "id": "baima-bridge" }`   | 同上（兼容指令名）            |
| **播放视频** | `{ "cmd": "video-play" }`                   | 播放当前点位视频（如有）      |
| **暂停视频** | `{ "cmd": "video-pause" }`                  | 暂停当前点位视频（如有）      |
| **快进视频** | `{ "cmd": "video-seek", "offset": 10 }`   | 快进 10 秒（offset 可为负数快退） |
| **快退视频** | `{ "cmd": "video-seek", "offset": -10 }`  | 快退 10 秒                    |
| **音量加大** | `{ "cmd": "video-volume", "delta": 0.1 }` | 音量增加 10%（0~1 范围）      |
| **音量减小** | `{ "cmd": "video-volume", "delta": -0.1 }`| 音量减小 10%                  |
| **静音**     | `{ "cmd": "video-mute", "muted": true }`  | 静音                          |
| **恢复音量** | `{ "cmd": "video-mute", "muted": false }` | 取消静音                      |

### 字段说明

- `cmd` —— 指令类型：`home` / `point` / `goto` / `video-play` / `video-pause` / `video-seek` / `video-volume` / `video-mute`
- `id` —— 点位标识，见下表
- `offset` —— 视频 seek 偏移量（秒），正数快进，负数快退
- `delta` —— 音量变化量（0~1），正数加大，负数减小
- `muted` —— 是否静音：`true` 静音，`false` 恢复

| 点位 ID          | 中文名         | 状态     |
| ---------------- | -------------- | -------- |
| `excavation`     | 绿色开挖料     | 已完成   |
| `navigation`     | 急弯通航       | 进行中   |
| `coating`        | 聚脲涂层       | 进行中   |
| `concrete`       | 抗冲磨混凝土   | 进行中   |
| `slope`          | 高边坡建模     | 进行中   |
| `baima-bridge`   | 白马大桥       | 已完成   |
| `blasting`       | 旧桥爆破       | 已完成   |
| `turbine`        | 水轮机         | 进行中   |

## 三、设备间互相发送（多屏互联）

支持向指定设备发送控制消息。

### 发送方式

底层通过 UEC WS 转发，`hub.json` 中 `id` 和 `target` 为 WS 连接身份标识，不影响设备间点对点发送。

**单设备发送：**

```typescript
const control = useControl()
control.sendTo('screen-2', { cmd: 'point', id: 'baima-bridge' })
```

**广播多设备：**

```typescript
;['screen-2', 'screen-3', 'screen-4', 'screen-5'].forEach((id) =>
  control.sendTo(id, { cmd: 'point', id: 'baima-bridge' })
)
```

### WS 消息格式

设备间发送的消息会被包裹为 `{ to, msg }`：

```json
{
  "to": "screen-2",
  "msg": "{ \"cmd\": \"point\", \"id\": \"baima-bridge\" }"
}
```

接收方副屏的 `useRemoteControl` 会自动解析 `msg` 中的 `cmd` 字段并触发对应 handler。

## 四、WS 连接配置

### 项目包 hub.json（一份，不需要每个屏都放）

```json
{
  "url": "wss://www.zzqxs.cn/uec/UECServer/ws/webSocketServer.do",
  "transport": "uec",
  "id": "research",
  "target": "research"
}
```

> **注意：** 项目包中只有**一份** `hub.json`，位于包根目录，**不需要**在 `displays/` 下再放。运行时每个屏读取同一份 hub.json，再叠加上设备级的 settings.json 区分身份。

### 部署时区分 5 个屏的 id

运行时合并优先级：**环境变量 > settings.json > 项目包 hub.json > 内置默认**。

部署时通过每台设备的 `settings.json` 覆盖 `hubId`：

```
%APPDATA%/exhi-client/settings.json
```

```json
{
  "hubId": "research-main",
  "hubTarget": "research"
}
```

各屏建议 id 对照：

| 屏幕           | displayId    | settings.json hubId | 中控发指令目标 |
| -------------- | ------------ | ------------------- | -------------- |
| 主屏           | `main`       | `research-main`     | `research-main` |
| 左上副屏       | `top-left`   | `research-tl`       | （不发）       |
| 左下副屏       | `bottom-left`| `research-bl`       | （不发）       |
| 右上副屏       | `top-right`  | `research-tr`       | （不发）       |
| 右下副屏       | `bottom-right`| `research-br`      | （不发）       |

- `hubId` —— 本设备身份标识（拼到 WS URL `?id=` 上）
- `hubTarget` —— 默认消息接收方（中控平台 ID）
- 心跳间隔：20 秒
- 重连间隔：3 秒（固定间隔）

## 五、项目交互说明

### 首页（待机态）

- 显示完整地图 + 8 个工程点位标记
- 标记分两种状态：已完成（橙色水滴）、进行中（蓝色菱形）
- 点击标记或右侧菜单选中点位

### 选中态

- 主屏：地图仅保留当前点位，显示点位详情图文
- 左上/右上副屏：展示该点位详情图文
- 左下/右下副屏：展示图片轮播卡片堆叠
- 部分点位（baima-bridge、blasting）支持视频播放/暂停

---

## 六、注意事项

1. `point` / `goto` 指令中的 `id` 必须存在于点位对照表中，否则无效。
2. `video-play` / `video-pause` 仅在当前选中的点位有视频素材时生效。
3. 所有消息通过 UEC WebSocket 服务转发，设备仅接收发给自己 `id` 的消息。
4. 部署时每个设备的 `hub.json` 中 `id` 需唯一，避免消息串线。
